# 架构与维护约定

`LocaleStack.Core` 是无 UI 依赖的安装协议实现，包含数据模型、路径与哈希验证、ZIP 校验、Steam 定位、官方 GitHub 下载源、安装状态及事务恢复。

`LocaleStack.App` 是 WPF 桌面入口，使用 MVVM 绑定与异步命令。长时间文件处理在后台线程运行，通过 `IProgress<OperationProgress>` 报告进度。UI 将同一时间的操作串行化，核心再使用文件锁跨进程互斥。游戏目录与本地设置分开保存。

`LocaleStack.Cli` 负责维护者工作流，读取原版与汉化文件生成标准包；不执行包内脚本，不使用游戏平台账号。发布目录只是元数据，补丁文件放 GitHub Releases。

`LocaleStack.Tests` 是无需测试框架依赖的隔离回归运行器。测试目录使用临时路径，每项测试独立构造文件与包，并验证实际文件内容或状态。网络测试注入 HTTP handler，不访问外网；Steam 测试构造真实 VDF / ACF 布局。

## 更改约定

协议语义的变更应同步更新 Models、运行时验证、JSON Schema、CLI 与格式文档。不兼容的变更递增 `schemaVersion`，不能静默改变旧字段含义。版本号为三段稳定版本。

替换目标、payload、备份与事务路径统一走 SafePaths。新的安装方式不应绕过指纹验证、原版备份、安装互斥和事务提交。恢复必须先验证全部当前文件及备份，避免部分恢复后才发现冲突。

下载来自官方 HTTPS 地址并验证大小与哈希。目录失败时使用缓存；首次运行有内置的 planned 条目。网络错误不能把计划中的游戏显示成已发布。

## 后续可扩展

需要另行设计与验证的功能：签名目录、多源订阅、Linux / Steam Deck、二进制差分补丁、依赖组件、游戏运行中托盘行为、可视化维护后台。目前接口没有把这些功能假装成已支持。
